# Pac-Man

PythonとMLXで制作中のPac-Manです。外部パッケージで生成した迷路を使い、移動・敵・アイテム・画面遷移を段階的に実装しています。

## 起動

現在のプロジェクト設定はPython 3.14以上です。`uv` と、MLXを表示できるX11のグラフィカル環境が必要です。

```bash
uv sync
uv pip install ./mazegenerator-2.1.0-py3-none-any.whl ./src/mlx-2.2-py3-none-any.whl
.venv/bin/python main.py
```

MLXと迷路生成パッケージは、現状では`pyproject.toml`の依存関係とは別に、同梱wheelからインストールします。

| プレイ中 | 矢印 / WASD | 移動、方向転換の予約 |
| プレイ中 | P | ポーズ |
| プレイ中 | C | 配色変更 |
| プレイ中 | `harnakam` を順に入力 | チートの有効・無効を切り替え |
| プレイ中・チート有効 | N | 次レベルへ移動 |
| プレイ中・チート有効 | F | 敵の移動を停止・再開 |

ホームの項目はゲーム開始・操作説明・ランキングの順です。初期選択はゲーム開始で、I/Hによる直接移動も使えます。ホームには保存済みランキングの先頭5件、ランキング専用画面には上位10件を表示します。

チートコマンドはShiftを押さずに入力します。途中まで一致したキーは移動やレベル移動へ渡さず、不一致なら入力位置をリセットします。チート解除時は敵の停止も解除します。停止中の敵にも接触判定はあります。

## 現在のゲーム動作

- レベル数と制限時間はConfigから取得します。現在のmain.pyの仮設定はサイズ変更確認用の10レベル、各90秒です。次レベルでは迷路を再生成します。
- プレイヤーは中央に最も近い通路から開始し、残機は3。次レベルへスコアと残機を引き継ぎます。
- 通常gum・スーパーgum・敵の得点はConfigから取得します。現在の既定値は10・50・200点です。四隅のスーパーgumで5秒間敵を食べられます。
- パワーアップ中は敵が青くなり、逃走Strategyで移動します。食べた敵は設定の得点を加算し、その敵の初期位置へ戻して5秒待機させます。待機中は描画・移動・接触判定を行わず、次レベルや死亡復帰などのリセットでは待機を解除します。
- ポーズ中は移動、レベルの残り時間、パワーアップの残り時間が止まります。
- 通常gumとスーパーgumをすべて食べるとステージクリア。最終レベルなら全クリアです。
- 時間切れはゲームオーバー。ただし同じフレームで最後のgumを食べた場合はクリアを優先します。
- HUDにレベル、得点、残機、制限時間を表示し、プレイ・ポーズ中のパワーアップ効果は下部の残り時間と中央へ縮むバーで示します。ホームや終了画面には効果表示を出しません。
- チート有効中はHUDに`CHEAT ON`を表示します。通常のHUDは`Lv`・`Score`・`Life`・`Time`の短い表記を使います。

`main.py`でPydanticの`Config`と`LevelConfig`を直接作成しています。JSONの読み込みはペアの担当で、まだ接続していません。保存先・残機・得点・レベル数・制限時間をゲームへ反映しています。

ウィンドウは画面サイズから余裕を引いた固定サイズです。`_update_layout()`で迷路に収まるセルサイズと中央寄せの`offset_x`・`offset_y`を計算します。設定ごとの迷路サイズで生成し、レベル変更時には敵の初期位置・キャラクター半径・gumの行列数も更新します。main.pyのテスト設定は先頭3レベルが15×15・25×15・15×25、残り7レベルが15×15です。

ホーム・操作説明・ランキング・ポーズ・ステージクリア・ゲームオーバー・全クリアは、`needs_redraw`が立ったときだけループから描画します。状態変更、メニュー選択、名前入力でフラグを立て、描画後に下ろします。ウィンドウ再表示イベントからは直接再描画します。プレイ中のFPS制限はありません。

各画面の文字は、MLXの英数字フォントの送り幅（1文字10ピクセル）から横中央を計算します。タイトル・本文・操作案内は行間をそろえ、ポーズの背景は文字が収まる大きさにします。HUDは上部、パワーアップ表示は下部に配置します。

メニューなどの静止画面は濃紺の背景とパネル、水色の枠で統一しています。本文は白、タイトルとホームの選択項目は黄色です。ポーズは迷路を残した上にパネルを重ね、パワーアップバーも暗い土台と黄色の残量で表示します。

ホームの上下選択では画面全体を消さず、メニュー部分だけを描き直します。透明画像で他の領域を残し、選択表示の文字数も一定にして、点滅と横位置の変化を抑えています。画面切り替えとウィンドウ再表示では全体を描き直します。

## ハイスコア

`HighscoreManager`は作成時にConfigの保存先（現在はカレントディレクトリの`scores.json`）を読み込みます。ファイルがなければ空で開始し、読み込み時と得点追加時に降順へ並べ替えます。追加時にはファイルへ保存します。

Pydanticの`ScoreEntry`（名前と得点）と`HighscoreData`を使います。

```json
{
  "scores": [
    {"name": "Alice", "score": 1200},
    {"name": "Bob", "score": 800}
  ]
}
```

現在同梱の`scores.json`は開発中のプレイ・テストデータです。Pydanticで名前1〜12文字・得点0以上を検証し、入力画面では空名を`kyonaha`として保存します。読み込み時の`OSError`・`ValidationError`、保存時の`OSError`を捕捉して続行します。保存失敗時もメモリ上の得点は残ります。UTF-8でないファイルへの対応や安全なファイル置換は未実装です。

## 構成

| ファイル | 役割 |
| --- | --- |
| `main.py` | 仮のConfig作成、迷路生成と起動 |
| `models/models.py` | ゲーム共通設定とレベル別設定のPydanticモデル |
| `visualize/maze_visualizer.py` | MLXの管理、入力、ゲーム進行、描画呼び出し |
| `visualize/maze.py` | 迷路、移動可否、中央付近の配置、全通路からのBFS距離表 |
| `visualize/movement.py` | セル間の移動と方向変更 |
| `visualize/player.py` | プレイヤー、得点、残機、パワーアップ |
| `visualize/ghost.py` / `strategy.py` | 敵の描画・移動と方向選択 |
| `visualize/pacgums.py` | 通常gumとスーパーgumの配置・消費・描画 |
| `visualize/collision.py` | 接触判定 |
| `visualize/gui.py` | 各画面、ランキング、HUD、バーの表示 |
| `visualize/cheating.py` | 順番入力のチートコマンド判定 |
| `visualize/highscore.py` | 得点モデルとJSONの保存・読み込み |
